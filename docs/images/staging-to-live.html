How a change goes from Staging to Live

DELA has two copies. Every change is tried on the practice copy first.

Staging

The practice copy. Only the Lawfecta Team and test accounts use it. Mistakes here hurt nobody.

→

Live

The real copy. Real members use it. It only changes when you push a tested version.

1

Claude builds the change

The new version goes onto Staging. You see it on Release Control as "Ready to test".

Claude
2

Automatic tests run

GitHub checks everything by itself. Green means every test passed.

GitHub
3

You test it with ChatGPT

Paste the test prompt Claude gives you into ChatGPT. Send ChatGPT's report back to Claude.

You
4

You say "it's ready"

On Release Control, tick "I tested this version on Staging and it is ready".

You
5

You press Push to Live

Enter your release password, then the 6 digit code sent to you. Only you can do this.

You
6

Live is watched for 15 minutes

DELA checks Live every minute. If all is well, it shows "Live now". Done.

Automatic

If something goes wrong

  • It goes back by itself. If Live has a problem during the watch, DELA returns to the last good version and tells you.
  • You can go back any time. Release Control, History, "Go back to this", then your password and code.
  • Emergency pause. One click stops all of DELA, or one part, for members. Click again to turn it back on.
  • Member data is safe. A push moves new screens and code only. It never copies or deletes anyone's data.

Lawfecta DELA · Release Control is the first tab in the DELA admin area (hirelegalhelp.com/dela-admin)
